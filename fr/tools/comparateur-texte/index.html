Vérificateur de différences : comment ça marche

Le AfroTools Diff Checker vous permet de comparer deux blocs de texte ou de code côte à côte et de voir instantanément chaque différence. Collez votre texte original à gauche et la version modifiée à droite, et l'outil met en évidence les ajouts, les suppressions et les modifications avec un code couleur clair : vert pour les lignes ajoutées, rouge pour les lignes supprimées et jaune pour le contenu modifié. La comparaison au niveau des mots identifie les caractères exacts qui ont changé dans chaque ligne, ce qui facilite la détection des modifications subtiles. L'outil fournit des statistiques montrant en un coup d'œil le nombre de lignes ajoutées, supprimées et inchangées. Les options de basculement vous permettent d'ignorer les différences d'espaces ou d'effectuer des comparaisons insensibles à la casse lorsque ces différences ne sont pas pertinentes pour votre révision. Cet outil de comparaison est inestimable pour les développeurs qui examinent les modifications de code, les rédacteurs qui comparent les brouillons de documents, les traducteurs qui vérifient les révisions de texte et tous ceux qui ont besoin d'identifier rapidement ce qui a changé entre deux versions. Toutes les comparaisons s'effectuent dans votre navigateur en temps réel : aucune donnée ne quitte votre appareil.

Questions fréquentes

Quels types de contenus puis-je comparer ?

Vous pouvez comparer n'importe quel texte brut : code source dans n'importe quel langage de programmation, fichiers de configuration, données JSON, XML, CSV, documents en prose ou tout autre contenu textuel.

À quoi sert « ignorer les espaces » ?

Lorsqu'il est activé, l'outil ignore les différences dans les espaces, les tabulations et les espaces de fin. Ceci est utile pour comparer du code qui peut avoir des styles d’indentation différents mais qui est par ailleurs identique.

Y a-t-il une limite de taille pour le texte que je peux comparer ?

Puisque la comparaison s'exécute dans votre navigateur, aucune limite n'est imposée par le serveur. Toutefois, les textes très volumineux (plus de 50 000 lignes) peuvent ralentir le rendu. Pour les documents et fichiers de code typiques, les performances sont instantanées.

Que signifient les couleurs dans la sortie diff ?

Les surlignages verts indiquent des lignes ou des mots ajoutés, les surlignages rouges indiquent le contenu supprimé et les lignes jaunes marquent les lignes qui ont été modifiées. La mise en surbrillance au niveau des mots dans les lignes montre exactement quels caractères ont changé.

Mon texte est-il envoyé à un serveur ?

Non. La comparaison est effectuée côté client dans votre navigateur en utilisant JavaScript. Utilisez un navigateur et un appareil que vous contrôlez et évitez de coller des secrets, des informations d'identification, des enregistrements clients privés ou des contrats confidentiels dans des exemples partagés.

Vérification et limites du Diff Checker

Vérification officielle/source

Ne collez pas de clés privées, de mots de passe, d'enregistrements clients ou de code source inédit dans un navigateur que vous ne contrôlez pas. Utilisez la comparaison comme aide à la révision, puis confirmez les modifications importantes du code, du contrat ou de la politique dans le système source.

Chemin d’exportation ou d’enregistrement

Utilisez les contrôles de sortie de page, copiez, imprimez, téléchargez ou enregistrez les brouillons lorsqu'ils sont disponibles, et conservez un enregistrement séparé avant de prendre des décisions concernant l'argent, les voyages, la carrière, les télécommunications ou les documents.

Vérification de révision

Utiliser la sortie différentielle comme aide à la révision, pas comme approbation

Comparez localement le texte original et modifié, changez de ligne ou de mot, puis copiez le résultat ou une note de révision locale.

Comparaison locale

Les deux volets sont comparés dans votre navigateur.

Que vérifier

  • Méthodologie : divisez les deux entrées en unités comparables, marquez les ajouts et les suppressions, puis résumez les lignes modifiées, ajoutées, supprimées et inchangées.
  • Examinez les modifications apportées aux espaces uniquement, les paramètres de casse, les extraits copiés, le code généré, le libellé juridique et le texte sensible avant de les partager.
  • Utilisez la différence copiée comme liste de contrôle pour les réviseurs, et non comme acceptation automatique.

Limites

  • Avertissement : aide à la comparaison locale uniquement, et non une approbation de code, une ligne rouge juridique, un examen de sécurité ou une certification de traduction.
  • La signification sémantique, le formatage caché, les fichiers binaires et les artefacts générés peuvent nécessiter un examen séparé.
  • Ne collez pas de secrets, d'informations d'identification, d'enregistrements clients privés ou de contrats confidentiels dans des exemples partagés.
