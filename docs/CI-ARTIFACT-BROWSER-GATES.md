# CI artifact browser gate ownership

Native metadata diagnostics record only HTTP status, response shape, expected job name, exact run/attempt matches and public start/status fields. HTTP400/401/403/404 and malformed or mismatched identity responses fail immediately; rejected bodies are never decoded or logged. Only transient request/visibility failures receive the existing bounded three reads. The current repository's tracked-path listing exceeds1MiB, so its source-manifest owner uses a bounded32MiB subprocess stdout budget while retaining every path and hash.

The CI prototype uses two independent hosted browser runners after one artifact producer. `Verify` and `Playwright smoke` retain their original workflow blocks. The required `Build and audit` status aggregates the producer and both browser groups; it fails if a job, original gate, report, identity check or deadline is unsuccessful or missing.

`scripts/ci-artifact-groups.json` records every original build step at pinned source commit a225e13f202da2f1e578e221bf14d4848c5a6099. Ten original steps belong to the producer; 32 complete browser steps belong to the two groups. The native command and environment strings preserve original specs, loops, grep, worker flags, retries, traces and timeout configurations. Groups execute their assigned steps in original relative order. Each Linux runner has its own network/filesystem namespace, so existing ports stay unchanged.

The producer executes the entire original French-finance step, including its `writeReleaseMetadata()` call, browser contracts and evidence collector, before sealing. That metadata call owns both `dist/status/release.json` and the generated function companion outside `dist`. The original generated-output parity command executes before seal and again after each browser group. Consumers never call the build or metadata writer and cannot reseal or restamp a mismatch.

The seal binds the checked-out commit/tree, GitHub event/ref, run/attempt, inventory, source bytes, exact dist content tree, both marker bytes and archive SHA256. Tar preserves file modes. Symlinks and unsupported file types are rejected. Consumers accept only the producer's manifest digest supplied by the job output, check archive SHA256 before extraction, then verify source/dist/marker bytes before and after each group. Fast tracked-source parity checks run at individual gate boundaries. A consumer rejects an existing `dist` directory rather than overlaying another artifact.

The producer's native job `started_at`, read through GitHub's read-only job API after the original checkout/Node setup, establishes a single absolute 75-minute acceptance deadline. At most three metadata reads with ten-second request deadlines and one-second waits accommodate delayed visibility; the helper requires a unique valid native start and never substitutes the current clock. The original checkout/setup time still consumes that native deadline. Producer sealing, consumer setup, every native browser command and the aggregate share this deadline. The runner terminates a gate's process group at expiry. Job queue/transfer/setup/hash time consumes this allowance; it cannot restart in a child job. A late setup/transfer/action also prevents acceptance, even if the runner has not yet started a gate. Existing native test budgets stay unchanged.

The two consumers repeat the original `npm ci` and Chromium installation commands, with the shared deadline, and invoke the original native Bash blocks. The only browser context expression in the current inventory, `${{ runner.temp }}`, resolves to that runner's native `RUNNER_TEMP`; unknown expressions fail closed. Per-gate logs and native test outputs are copied into separate run/attempt/group/step evidence. The original owner-specific Swahili fuel output is preserved too. Failure evidence is uploaded with `always()` and never reused as success.

When adding a CI browser gate, update the explicit inventory and pinned preservation baseline in the same reviewed change. Do not append an ordinary gate to an unverified group or edit its command to make a pilot pass. `tests/ci-artifact-orchestration.test.js` mechanically verifies the complete original producer/browser coverage and preserved Verify/smoke blocks, and exercises missing/duplicate/skipped/cancelled/failed reports, identity mismatches, artifact/source tampering and deadline expiry.

This candidate is a prototype until an exact-commit remote run passes every original gate and verifies both consumers against one sealed artifact. No modeled time improvement is an achieved speedup. The publisher still owns integration, production deployment and live proof; this workflow does not invoke Netlify and does not change the maximum of three concurrent Netlify builds.

GitHub artifact transport is independent of this hard gate: a transport digest mismatch can be a warning, so explicit manifest/archive mismatches must fail. Artifacts are immutable between jobs. [GitHub artifact documentation](https://docs.github.com/en/actions/tutorials/store-and-share-data). The aggregate uses `needs` plus an unconditional completion path so downstream failure is reported. [GitHub job conditions](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-jobs). Original unspecified Linux shell behavior stays `bash -e {0}`, using a script file containing the exact run block. [GitHub shell syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#jobsjob_idstepsshell). The producer deadline binds the exact run-attempt job's native start through the read-only endpoint. [GitHub job API](https://docs.github.com/en/rest/actions/workflow-jobs#list-jobs-for-a-workflow-run-attempt).
