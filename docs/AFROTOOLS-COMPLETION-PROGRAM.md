## Evidence contract

Every finding needs an issue key, affected route or file, evidence date and layer,
source owner, reproduction, priority, current status, next action, and acceptance
condition. Reuse existing issue/candidate ownership where it exists.

Keep these layers separate:

- Source/static inspection: declarations, tags, links, syntax, content, registries.
- Repository tests: passing fixtures and contract checks at the recorded commit.
- Local browser load: rendering, runtime exceptions, and local route behavior.
- Workflow/action proof: calculations, uploads, export contents, backup/restore,
  keyboard behavior, consent, and failure states using synthetic input.
- Live service proof: provider configuration, scheduled invocations, Supabase
  policies/migrations and data freshness, account save/reload, and billing.
- Production proof: exact deployment SHA and observed deployed behavior.
- Editorial review: factual correctness, useful content, and language quality.

A static grade, HTTP 200, translation inventory, green test suite, or deployment
marked ready is not by itself evidence that every user workflow is complete.
An unknown result stays unverified. Historical reports remain dated evidence and
must not be described as a fresh execution.

## Completion gates

| Gate | Acceptance condition |
| --- | --- |
| Inventory | Every current route/app has an owner, declared purpose, status, and acceptance entry; aliases, embeds, fallbacks and private pages are classified. |
| Free apps | Core inputs, correct result oracle, meaningful validation, and promised copy/download/export paths pass; guests can use intended free workflows. |
| Pro | Each app's promised operating workflows work; account/device boundaries are accurate; paid access, saves, reloads, permissions, billing and failure paths are verified. |
| SEO/tags | Canonicals, intended indexability, hreflang, sitemap membership, titles/descriptions, social metadata and structured data agree with served routes and content. |
| Search quality | Thin/duplicate/ambiguous pages and snippet review signals receive an explicit evidence-based disposition; available GSC evidence informs priorities. Rankings are not a completion guarantee. |
| Languages | Each claimed translated workflow has usable local-language controls, results, validation, exports and task content. Fallbacks remain clearly labelled and excluded from false equivalents. Native-speaker/editorial gaps remain explicit. |
| Trust/data | Changing rates, laws, fees and deadlines have correct sources, effective dates, assumptions and visible freshness/confidence. Failed sources cannot manufacture current data. |
| Privacy/security | Sensitive content stays local by default; network/AI sends have explicit consent; no raw sensitive analytics/logging; auth and data isolation pass; publish artifacts exclude internals. |
| Accessibility/mobile | Visible/accessible names, keyboard/focus/modal behavior, contrast, status messages, reduced motion and small-screen layout pass on the affected workflows. |
| Product concept | Users can find a country-specific task, understand the result and continue/export; product claims match actual behavior; Pro value and previews are understandable. |
| Operations/release | Required scheduled lanes have fresh evidence; build/security/dist checks pass; release candidates have exact-SHA production proof and rollback instructions. |
| Weekly handover | No open completion blockers or undisposed unverified required workflows; routine freshness work has an owner and alerts; a weekly checklist and recovery instructions have been exercised. |

Do not infer approval to retire routes, remove product offerings, or reduce language
coverage. Review-only recommendations remain pending until a concrete decision is
authorized. Do not spend money, create accounts, send real notifications, or execute
real payments as an audit shortcut.

performance and high-impression pages, language regressions, dependency/security
advisories, and new legal/rate/deadline changes. Run relevant checks on small fixes,

register. Time-sensitive automated feeds retain their appropriate cadence; weekly
human review does not mean deliberately stale daily data.
