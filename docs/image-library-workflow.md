# Image library and daily batches

The image director works from `data/image-generation/image-library.json`, generated by `node scripts/build-image-library.js`. This inventories product assets, hashes exact duplicates, records local reference evidence, and assigns unmatched files to review queues. It does not prove live deployment, complete dynamic usage, ownership/licensing, or absence of embedded text.

`reviewed-shared-artwork.json` owns visually reviewed additions to the shared tool-card index. Run `node scripts/build-tool-image-index.js` after adding an approved tool id. Never equate a filename match with visual approval. Keep one canonical file for a subject across equivalent translated pages, and localize captions/alt text in HTML. Text-bearing images remain language-specific.

`recipe-image-aliases.json` maps six duplicate same-dish catalogue entries to existing photos. The static resolver, cuisine intelligence and browser pipeline share those canonical paths. The browser prioritizes the known image from cuisine intelligence, avoiding failed probes for the aliased filename. These aliases do not alter recipe routes, names or ingredients. The tracked `tools/afrokitchen/image-pipeline.js` is the only available source for that browser helper; no separate readable owner exists.

The September 8 kitchen import has a hashed 63-file receipt. `node scripts/import-reviewed-kitchen-images.js` moves the 60 approved files, holds three rejected files, regenerates cuisine intelligence from the saved manifest, and refreshes only image content on the affected existing pages. It uses no live database. Re-running retains the same intake; a new delivery needs its own reviewed intake rather than silently approving files.

`next-200.json`, `next-200.csv` (UTF-8 BOM), and `next-200.md` contain the current generation batch. Every row has an existing destination route, exact output filename, prompt, dimensions, priority and alt text. Serving-detail prompts also name the existing reference image. Reuse this queue until the images arrive; do not generate another copy of a pending image. Once delivered assets are reviewed/imported, run `node scripts/build-image-library.js --batch=YYYY-MM-DD` to select remaining gaps. This command prepares prompts; it does not invoke a paid generator or publish files.

After updating the card index, generate its browser counterpart with `node scripts/minify.js --only=tool-registry`.

Validation: `node tests/image-library.test.js`, `node scripts/build-tool-image-index.js --check`, `node scripts/repair-image-references.js --check`, plus browser image loading and mobile layout checks. The dashboard consumes the two JSON outputs and keeps operator status separate from generated file-existence evidence.
