# PDF watermark parity repair — 26 September 2026

## Outcome and scope

The English, French and Swahili watermark routes now share a source-owned runtime that invalidates obsolete downloads, keeps the newest image selection, publishes previews only for the current settings, and reports safe native-language feedback. Swahili downloads use the same local guest workflow as English and French. A reproduced desktop overlap, where the sticky preview covered Download, is removed by the shared preview owner. Batch ZIP outputs also retain every document when source names normalize to the same filename.

Routes: `/tools/pdf-watermark/`, `/fr/tools/filigrane-pdf/`, `/sw/zana/watermark-pdf/`.

This is a bounded source/browser repair. It does not establish full catalogue parity or production deployment proof.

## Source and generated files

- `assets/js/pages/pdf-watermark.js`: readable runtime owner recovered from the previous sole minified runtime. Adds generation ownership, strict page ranges, native feedback, accurate PDF-based previews and desktop control access.
- `scripts/minify.js` and `tools/pdf-watermark/app.js`: explicit source/output pair. Generated bytes match the configured production minifier exactly.
- `scripts/build-swahili-document-pdf-parity.js` and `sw/zana/watermark-pdf/index.html`: watermark row and generated route use the existing local guest-download contract.
- `tests/e2e/pdf-watermark-language-parity.spec.js`: real downloaded PDFs and ZIP members, rendered pixels, native errors, keyboard upload, mobile width and asynchronous races.

Base: `94af89b783f2779dc3a8c2db5cf4e2d34b6c2641`. At recovery, verified `origin/main` was `7a5c7f8fae971d1ffadea09de973e3e4fb4b7009`; this isolated branch was not reset or merged with it. Unrelated saved `test-results/.last-run.json` remains unstaged.

## Verified behavior

- Actual selected-page/all-page text and opaque PNG watermarks retain original text, page order, dimensions and a known green vector marker across all three locales.
- Behind-content output and two-file ZIP downloads work for guests. ZIP CRC checks and extraction confirm both PDFs, original text and selected-page watermarks.
- The filename-collision baseline reproduced loss: four distinct source names yielded only two accessible ZIP members. Output names now receive deterministic suffixes, with case-insensitive uniqueness, so sanitized/Unicode-fallback names cannot overwrite another member.
- Editing settings or adding a file during generation removes obsolete results. Regeneration contains the new synthetic text.
- Delayed image reads and delayed failures cannot replace the newer image. Invalid image replacement clears old image bytes and disables Apply.
- Delayed actual preview painting cannot overwrite a newer preview. The preview and independently rendered downloaded PDF have identical pixels at the same scale, including the chosen font and offset.
- Native range/invalid-PDF messages expose no raw parser exception. Scientific notation is rejected as a page number.
- At 320px, tested upload keyboard controls work and the page has no horizontal overflow. Ordinary desktop Download clicks succeed without forcing clicks or removing page elements.

The normalized bodies of the six existing drawing/serialization helpers (`x`, `S`, `C`, `E`, `U`, `P`) match the base runtime. The repair changes lifecycle, preview and feedback around those existing export operations.

## Oversized rotated watermark limitation — explicitly checked

A 60pt `NEW MARK` watermark rotated -45 degrees on a 320×420pt page clips at the left and bottom. Its PDF text origin is approximately (-8.3, 175.2) points. The application continues to honor the user-selected size/rotation/offset rather than automatically shrinking or repositioning the watermark.

Three additional browser cases prove that this exact oversized setting produces identical visible preview and downloaded-PDF raster pixels in EN/FR/SW. The PDF stream contains the new text; text extraction can omit clipped parts. Both the ordinary and oversized raster evidence were visually inspected. This limitation is therefore visible in the preview; it is not claimed to be automatic text fitting or lossless extraction of off-page content.

## Risks and remaining evidence

- No real user documents were used, uploaded, logged or added to evidence. Processing remains local; no AI/server functionality or analytics event changes were introduced.
- Existing routes, canonical URLs and language alternatives are unchanged.
- This proof covers text, opaque PNG, ordinary unrotated source pages, behind-content mode and simple two-file ZIPs. JPEG/WebP/EXIF/transparency, rotated/cropped source pages, encrypted or signed PDFs, annotations/forms, complex scripts, very large files and exhaustive keyboard/assistive-technology behavior remain unverified.
- Under-content output reconstructs visual pages; this proof does not establish preservation of document-level interactive structures.
- Ancillary shared Share as Image copy/functionality and whole-page linguistic quality were not assessed here.
- Full rebuild, publish-artifact checks, broader integration tests and deployment remain the coordinator's release responsibility.
- Rollback: revert this scoped commit and regenerate its minified/runtime and Swahili page outputs through their owners.
